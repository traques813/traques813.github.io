Unit 1 established the foundation for the rest of the module by requiring the setup of a structured GitHub e-portfolio. Creating a repository with an organised directory layout highlighted why version control underpins reproducibility and transparency in data workflows (Blischak, Davenport & Wilson, 2016).  

A key part of this unit was comparing common machine-readable formats such as CSV, JSON and XML. While CSV offers simplicity through flat structure, JSON supports nested hierarchies, and XML provides flexible tagging—though often with higher parsing overhead (Crockford, 2006; Bray et al., 2008). Understanding the strengths and constraints of each format established why data wrangling tasks prioritise consistency and structure before analysis.

These early tasks also stressed the importance of schema clarity. Ambiguous or undocumented structures introduce errors that compound during cleaning and transformation (Pyle, 1999). Establishing naming conventions and folder structures at this stage helped avoid these issues later.

Unit 1 did not involve complex coding but instead created the working environment for later units, emphasising organisation, traceability and structured documentation.
